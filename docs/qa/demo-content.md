# Demonstration dataset

The administrator dashboard contains **Load demonstration content**. It calls an authenticated, admin-only, same-origin POST `/api/demo` with an explicit confirmation marker. The route allows three attempts per hour per client IP. It is a controlled fixture import, not an SQL executor or a public signup route.

The dataset is inserted in one transaction, serialized with a PostgreSQL advisory lock. A dedicated fixed demo-year ID prevents duplicate imports. Existing accounts, passwords and records are not overwritten. An existing current academic year is preserved; the demo year becomes current only when none exists.

All account names, academic resource names, notices, invoices, and profile identifiers are visibly marked DEMO. Emails use the reserved `example.invalid` domain; addresses are fictional and no real contact information is generated. A high-entropy random password is bcrypt-hashed and discarded; no usable default demo password is published, returned or logged. Demo accounts receive student, parent or teacher roles only, never admin. Authorized administrators can reset an individual demo account through the normal account-recovery workflow if interactive role demonstrations are needed.

## Content

| Module | Included |
|---|---|
| Accounts | 16 students, 8 guardians, 3 teachers; existing administrator retained |
| Academic setup | 1 demo year, 2 terms, 2 classes, 2 sections, 3 subjects |
| Students and families | 16 profiles, 16 enrollments, 8 guardian profiles and 16 family links |
| Teaching | 3 staff profiles, 2 class-teacher and 6 subject-teacher assignments |
| Timetable | 2 rooms, 30 weekly sessions, conflict-free teacher/section/room allocation |
| Attendance | 80 entries over the last 5 weekdays, including a correction and audit trail |
| Fees | 3 structures, 17 invoices, 10 manual payment records, paid/part-paid/unpaid and overdue balances; INR and USD kept separate |
| Exams | 1 custom grading scale, 4 exams (2 published, 2 draft), 16 candidates, 6 papers, 48 marks and published report cards |
| Notices | 6 announcements including targeted, published, draft and scheduled states; 3 read acknowledgments |
| Audit | Attendance, fee, exam, mark, timetable and notice events generated by normal database triggers |

Manual payment entries are fictional demonstration records. No payment processor is invoked and no funds are transferred. The importer does not fabricate dashboard metrics: the dashboard continues reading its normal authorized database aggregates.

## Verification and preservation

Run `npm test --prefix backend`, `npm test --prefix frontend`, and `npm run build --prefix frontend`. Demo integration tests cover import authorization, untrusted origins, malformed confirmation, rate limiting, populated module endpoints, role/family scoping, report cards, audit history, repeat imports, transaction rollback, and preservation of an existing current year.

No destructive cleanup endpoint is included. Audit and financial history is intentionally protected by the schema. Before later replacing this demonstration environment with real school records, take a backup and plan a separate clean database and deployment rather than bypassing history constraints or mass-deleting live tables.
